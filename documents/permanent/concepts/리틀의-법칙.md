# 리틀의 법칙(Little's Law)

## 정의

안정된 시스템에서 평균 항목 수(L) = 처리율(λ) × 평균 체류 시간(W)이 성립한다는 대기행렬 이론의 법칙; DB 커넥션 풀 진단에서는 **TPS = 활성 커넥션 수 ÷ 쿼리 실행 시간(초)** 형태로 변형해 활용한다.

## 맥락

DB 성능 튜닝에서 리틀의 법칙은 **풀 사이즈를 정하는 공식이 아니라 "풀 부족 vs 쿼리 성능 부족을 구별하는 진단 도구"**다.

```
TPS = 활성 커넥션 수 ÷ 쿼리 실행 시간(초)
```

활용 방법:
- 활성 커넥션이 맥스 풀의 ~90%에 도달하면 처리량 증가 방법 검토.
- 목표 TPS 미달 시 처방 순서: ① 쿼리 실행 시간 단축 우선(쿼리 실행 시간 절반 → TPS 2배), ② DB 코어 여력이 있으면 풀 확장, ③ 그래도 미달 시 DB 자원 증설.

이 공식은 [[db-커넥션-풀]] 사이징뿐 아니라 [[쓰레드]] 풀·HTTP 클라이언트 풀 등 모든 풀 시스템의 진단에 동일하게 적용된다.
