# 컨텍스트 스위칭(Context Switching)

## 정의

CPU가 현재 실행 중인 [[프로세스]] 또는 [[쓰레드]]의 상태(레지스터·프로그램 카운터·스택 포인터 등)를 저장하고 다른 프로세스/스레드의 상태를 불러와 실행을 전환하는 운영체제의 핵심 메커니즘.

## 맥락

컨텍스트 스위칭은 멀티태스킹을 가능하게 하는 동시에 비용을 수반한다:

- **직접 비용**: 현재 프로세스/스레드 상태를 PCB(Process Control Block) 또는 TCB(Thread Control Block)에 저장하고 새 상태를 불러오는 CPU 사이클 소모.
- **간접 비용**: 스위칭 시 L1/L2 캐시가 무효화되어 다음 실행 시 캐시 미스 증가 → 메모리 접근 횟수 증가. 이 간접 비용이 직접 비용보다 클 수 있다.

**DB 커넥션 풀 과다 시 컨텍스트 스위칭 문제**: 코어 8개에 스레드 200개가 활성화되면 CPU가 스레드 교체에 시간을 소모하는 것은 물론, 교체마다 L1/L2 캐시가 무효화되어 DB 쿼리 처리 효율이 급격히 저하된다. 이것이 [[db-커넥션-풀]] 사이즈를 물리 코어 수 × 2로 제한해야 하는 핵심 이유 중 하나다. 같은 원리가 [[쓰레드]] 풀·HTTP 클라이언트 풀 등 모든 풀 시스템에 적용된다(USL — Universal Scalability Law).

컨텍스트 스위칭 비용을 줄이는 방법:
- 프로세스보다 스레드 사용 (스레드 스위칭이 더 가볍다 — 같은 메모리 공간 공유)
- 동시 활성 스레드/프로세스 수를 CPU 코어 수에 맞게 제한
- 비동기 I/O 활용으로 I/O 대기 중 스위칭 필요성 감소
