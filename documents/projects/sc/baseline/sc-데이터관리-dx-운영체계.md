# 고객사 데이터 관리 DX 운영 체계

## 요구 개요

고객사는 네트워크 공유폴더(사실상 데스크탑 파일 서버)에 데이터가 집중되어 위치 파악·최신성·권한·검색·보존·AI 활용의 6가지 구조적 문제를 겪고 있으며, 이를 단순 저장소 이전이 아닌 메타데이터 중심의 DX 운영 체계로 전환하기를 요구한다. 핵심 방향은 레거시 데이터를 먼저 메타데이터화하고 신규 데이터는 생성 시점부터 표준 정책으로 자동 수집하는 이원화 접근이다. 데이터를 Hot/Warm/Cold 라이프사이클로 분리하고, 부서·고객사·프로젝트·문서유형·권한·보존정책의 6축 다차원 메타데이터(PARA는 보조 축)로 설계하며, RBAC 권한을 검색과 Graph RAG 전반에 관철해 권한 없는 문서는 존재 여부조차 노출하지 않도록 한다. 최종적으로 통합검색 포털과 운영 대시보드를 통해 데이터를 관리 가능한 자산으로 전환하고 AI 검색까지 확장하는 것이 목표다.

## 기능 목록

- [[legacy-scan-catalog]] — 기존 공유폴더 전체 스캔으로 파일 목록·기본 메타데이터를 추출하고 활용 상태별로 분류하는 레거시 목록화 기능
- [[sc-파일-데이터관리]] — 6축 다차원 메타데이터 모델로 파일 위치·속성을 등록·관리하는 중앙 메타데이터 카탈로그
- [[auto-ingest-agent]] — 신규 파일 저장 시 생성 이벤트를 감지해 카탈로그에 자동 등록하고 권한·보존 정책을 연결하는 감시/등록 에이전트
- [[realtime-tracking]] — 이벤트 기반 감시와 주기적 전체 스캔을 병행해 변경을 반영·보정하고 변경 이력을 남기는 실시간 트래킹
- [[data-lifecycle]] — 사용 빈도·보존 필요성에 따라 Hot/Warm/Cold로 분리하고 아카이브 전환·폐기 승인을 운영하는 라이프사이클 정책
- [[sc-로그인-권한관리]] — 사용자·문서·정책 단위로 접근 범위를 판단해 검색·AI 활용 전반에 관철되는 RBAC 접근권한 정책
- [[sc-통합검색]] — 인증·역할 확인 후 메타데이터 기반으로 검색하고 조회/다운로드로 이어주는 통합검색 포털
- [[graph-rag-search]] — RBAC로 필터링한 허용 문서만 대상으로 Graph/Vector 검색·AI 답변을 생성하고 권한 없는 문서는 존재조차 숨기는 Graph RAG 검색
- [[sc-메인-대시보드]] — 데이터 현황·증가량·보존 상태·리스크와 DX 성과 지표를 보여주는 운영 대시보드

## 원본 맥락

본 요구는 고객사(sc)의 "데이터 관리 DX 운영 체계 제안서" docx에서 도출되었다. 별도 NAS·문서관리시스템 없이 공유폴더를 파일 서버로 써 온 탓에 담당자 의존·중복·최신본 혼선·권한 불명확 문제가 커졌고, 4개 Phase(현황 진단→메타데이터화→신규 운영 정책→검색/AI 활용)의 단계적 도입과 우선순위·저장소·운영 책임·적용 범위에 대한 경영진 의사결정을 요구하고 있다.
