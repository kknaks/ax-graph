# 자동 수집 에이전트

> 한 줄 정의: 사용자가 표준 저장 위치에 파일을 저장하면 / 파일 감시·등록 에이전트가 생성 이벤트를 감지해 카탈로그 등록·권한 정책 연결·검색 인덱스 갱신을 자동 수행하여 / 신규 데이터를 등록 절차 없이 관리 가능한 자산으로 만든다.

## 1. 요구 배경
- **현재 불편(as-is)**: 신규 파일이 공유폴더에 그대로 쌓여 위치·권한·맥락이 정리되지 않는다. 원문은 "문서 위치/권한/맥락이 정리되지 않음"을 AI 활용의 장애로, "파일이 어디에 있는지 담당자 기억에 의존"하는 상태를 리스크로 지적한다. 사용자가 별도 시스템에 수동 등록해야 한다면 운영이 지속되지 못한다.
- **필요 이유**: 원문의 원칙대로 "신규 파일은 저장 시점부터 자동으로 등록"하게 하여, 사람의 개입 없이 생성 시점부터 메타데이터·권한이 연결되도록 한다.

## 2. 기능 정의
- 표준 저장 위치의 파일 생성 이벤트를 감시해 감지한다.
- 감지한 파일의 위치·속성을 메타데이터 카탈로그에 자동 등록한다.
- 카탈로그가 권한/보존 정책 서비스에 분류 및 권한 정책을 요청한다.
- 정책 서비스가 반환한 접근권한·보존기간·민감도를 등록된 파일에 연결한다.
- 등록·연결된 메타데이터로 검색 인덱스를 갱신해 권한 내 검색이 가능하게 한다.

## 3. 유저 플로우 (반드시 표, 케이스별)

| 케이스 | 행동 (사용자가 한다) | 과정 (시스템이 처리) | 결과 (산출물) |
|---|---|---|---|
| 정상 | 표준 저장 위치에 파일을 저장한다 | 저장소가 생성 이벤트를 에이전트에 전달 → 에이전트가 위치·속성을 카탈로그에 등록 → 카탈로그가 정책 서비스에 요청 → 접근권한·보존기간·민감도 반환·연결 → 검색 인덱스 갱신 | 권한·보존·민감도가 연결된 카탈로그 항목과 갱신된 검색 인덱스 |
| 예외 | 표준 저장 위치에 파일을 저장한다 | 이벤트 감시가 놓친 파일은 주기적 전체 스캔이 누락으로 확인해 보정 등록한다 | 이벤트 누락 파일도 카탈로그에 뒤늦게 등록되어 인덱스에 반영 |

## 4. 예시 (최소 2개, 실제 문장 인용)
- **입력**: 원문 원칙 "신규 파일은 저장 시점부터 자동으로 등록한다"에 따라 사용자가 표준 저장소에 계약서 파일을 저장한다.
  - **기대 출력**: 파일 위치·속성이 카탈로그에 등록되고 접근권한·보존기간·민감도가 연결된 항목이 생성된다.
- **입력**: 원문 흐름 "파일 생성 이벤트 → 파일 위치/속성 등록 → 분류 및 권한 정책 요청 → 접근권한/보존기간/민감도 반환 → 검색 인덱스 갱신"의 정책 반환 단계.
  - **기대 출력**: 반환된 민감도·보존기간이 메타데이터에 반영되고 검색 인덱스가 갱신되어 권한 내 사용자만 해당 파일을 검색·질의할 수 있다.

## 5. 상세 요구 (번호 목록, "~해야 한다")
1. 표준 저장 위치의 파일 생성 이벤트를 감지해야 한다.
2. 감지 즉시 파일의 위치·속성을 메타데이터 카탈로그에 등록해야 한다.
3. 카탈로그는 권한/보존 정책 서비스에 분류 및 권한 정책을 요청해야 한다.
4. 정책 서비스가 반환한 접근권한·보존기간·민감도를 해당 파일 메타데이터에 연결해야 한다.
5. 등록·연결이 끝나면 검색 인덱스를 갱신해야 한다.
6. 이벤트 감시가 놓친 파일은 주기적 전체 스캔으로 누락을 보정해 등록해야 한다.

## 6. 다루는 데이터 (해당 시)
- 입력: 파일 생성 이벤트, 파일 위치(file_path)·속성.
- 저장: 카탈로그 메타데이터(위치·속성·접근권한·보존기간·민감도).
- 출력: 갱신된 검색 인덱스 항목.

## 7. 수용 기준 (체크박스 최소 3개, 참/거짓 판정 가능)
- [ ] 표준 저장 위치에 파일을 저장하면 사용자 개입 없이 카탈로그 항목이 생성된다.
- [ ] 생성된 항목에 접근권한·보존기간·민감도 세 값이 모두 연결된다.
- [ ] 등록 후 해당 파일이 검색 인덱스에서 권한 내 사용자에게 검색된다.
- [ ] 이벤트 감시가 놓친 파일이 주기적 전체 스캔으로 카탈로그에 보정 등록된다.
