# 데이터 라이프사이클

> 한 줄 정의: 데이터 관리자가 사용 빈도·보존 필요성 기준으로 데이터를 Hot/Warm/Cold 3단계로 자동 분리·전환하면, 회사는 저장 비용을 줄이고 만료 데이터를 통제된 절차로 보존/폐기한다.

## 1. 요구 배경
- **현재 불편(as-is)**: 지금은 오래된 데이터가 최신 데이터와 계속 뒤섞여 있어 정리 기준이 없다. 원문은 보존 항목의 현재 문제를 "오래된 데이터가 계속 혼재"라 적고, 그 경영 리스크로 "저장 비용 증가, 정리 불가"를 든다. 사용 빈도가 낮은 데이터도 빠른 접근 저장소에 그대로 남아 비용과 혼선을 키운다.
- **필요 이유**: 데이터를 사용 빈도·보존 필요성에 따라 3단계로 분리 운영하면 오래된 데이터는 장기 보관소로 내리고 최신 데이터만 빠른 접근 영역에 남겨 혼재와 비용 문제를 없앤다.

## 2. 기능 정의
- 데이터를 Hot(최근 1년, 진행 중 업무)/Warm(1~3년, 참조 가능성)/Cold(3년 이상, 장기 보존) 3단계로 분류한다.
- 보존 기간이 경과하면 상위 단계에서 하위 단계로 전환한다(Hot→Warm→Cold).
- Cold 아카이브 전환 시 원본은 장기 보관소로 이동하고 메타데이터는 그대로 유지한다.
- Cold 이후 보존 만료 검토에서 법적/계약상 보존 필요 여부를 판정한다.
- 보존이 필요하면 Cold를 유지하고, 필요 없으면 폐기 승인 프로세스로 넘긴다.

## 3. 유저 플로우 (반드시 표, 케이스별)

| 케이스 | 행동 (사용자가 한다) | 과정 (시스템이 처리) | 결과 (산출물) |
|---|---|---|---|
| 정상 | 데이터 관리자가 보존 만료 검토 대상을 확인한다 | 사용 빈도·경과 기간으로 Hot/Warm/Cold 판정 후 Cold 아카이브로 전환, 원본은 장기 보관소로 이동하고 메타데이터는 유지 | 원본은 장기 보관, 메타데이터 중심으로 조회 가능한 Cold 데이터 |
| 예외 | 데이터 관리자가 Cold 만료 데이터의 보존 필요 여부를 검토한다 | 법적/계약상 보존 필요면 Cold 유지, 불필요하면 폐기 승인 프로세스로 진행 | 보존 유지(Cold) 또는 승인 후 폐기 처리된 데이터 |

## 4. 예시 (최소 2개, 실제 문장 인용)
- **입력**: 원문 표의 Cold 정의 "3년 이상, 장기 보존" 대상 데이터.
  - **기대 출력**: "원본은 아카이브, 메타데이터 중심 조회" 상태로 전환되어 원본만 장기 보관소로 이동한다.
- **입력**: 원문 라이프사이클 흐름의 "보존 만료 검토" 단계에 도달한 Cold 데이터.
  - **기대 출력**: "법적/계약상 보존 필요?"가 예면 Cold 유지, 아니오면 "폐기 승인 프로세스"로 진행.

## 5. 상세 요구 (번호 목록, "~해야 한다")
1. 데이터는 사용 빈도와 보존 필요성에 따라 Hot/Warm/Cold 3단계로 분리 운영해야 한다.
2. Hot은 최근 1년·진행 중 업무로 빠른 접근 저장소 중심으로 운영해야 한다.
3. Warm은 1~3년·참조 가능성 있는 데이터로 검색은 가능하되 접근 빈도가 낮은 영역에 두어야 한다.
4. Cold는 3년 이상 데이터로 원본은 아카이브하고 메타데이터 중심으로 조회하게 해야 한다.
5. 보존 기간이 경과하면 아카이브 전환을 수행해야 한다.
6. 아카이브 전환 후에도 메타데이터는 유지하고 원본만 장기 보관소로 이동해야 한다.
7. Cold 이후 보존 만료 검토에서 법적/계약상 보존 필요 여부를 판정해야 한다.
8. 보존이 필요하면 Cold를 유지하고, 필요 없으면 폐기 승인 프로세스로 진행해야 한다.

## 6. 다루는 데이터 (해당 시)
- 입력: 파일의 사용 빈도·마지막 사용 시점·생성 경과 기간.
- 저장: 보존 단계(storage_tier: Hot/Warm/Cold), 보존 기간(retention_period), 법적/계약상 보존 여부.
- 출력: 단계 전환 결과, 아카이브 후 유지되는 메타데이터, 폐기 승인 대상 목록.

## 7. 수용 기준 (체크박스 최소 3개, 참/거짓 판정 가능)
- [ ] 데이터가 Hot/Warm/Cold 3단계 중 하나로 분류된다.
- [ ] 최근 1년 데이터는 Hot, 1~3년은 Warm, 3년 이상은 Cold로 판정된다.
- [ ] Cold 아카이브 전환 후 원본은 장기 보관소로 이동하고 메타데이터는 유지된다.
- [ ] Cold 만료 검토에서 법적/계약상 보존이 필요하면 Cold가 유지된다.
- [ ] 보존이 불필요한 데이터는 폐기 승인 프로세스를 거친 뒤에만 폐기된다.
