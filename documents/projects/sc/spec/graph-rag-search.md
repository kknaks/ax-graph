# Graph RAG 검색

> 한 줄 정의: 사용자가 질문하면 / 시스템이 인증·역할을 확인해 접근 가능한 문서만 검색·AI 답변으로 / 권한 안의 결과와 출처를 얻는다.

## 1. 요구 배경
- **현재 불편(as-is)**: 문서가 폴더/파일명 기반 수동 검색에 의존하고 권한은 "폴더 권한 중심의 느슨한 통제"에 머물러 있어 민감 데이터 노출 위험이 크다. 원문은 "AI 검색과 Graph RAG는 반드시 권한 정책 위에서 동작해야 한다"고 못박는다.
- **필요 이유**: 인증·역할 확인 후 RBAC 조건으로 문서 범위를 좁혀 검색하므로, 권한 없는 문서가 결과·요약·근거에 새지 않는다.

## 2. 기능 정의
- **핵심 동작**: 사용자 질문을 받아 사용자 인증을 수행한다.
- 인증된 사용자의 역할/부서/그룹을 확인해 접근 가능한 문서 범위를 계산한다.
- RBAC 조건으로 메타데이터를 필터링해 허용 문서만 대상으로 삼는다.
- 허용 문서에 대해서만 Graph/Vector 검색을 수행하고 AI 답변과 출처를 생성한다.
- 권한 없는 문서는 결과·요약·근거에서 제외하고 문서 존재 여부조차 노출하지 않는다.

## 3. 유저 플로우 (반드시 표, 케이스별)

| 케이스 | 행동 (사용자가 한다) | 과정 (시스템이 처리) | 결과 (산출물) |
|---|---|---|---|
| 정상 | 접근 권한이 있는 주제로 질문한다 | 인증→역할/부서/그룹 확인→접근 범위 계산→RBAC 메타데이터 필터링→허용 문서만 Graph/Vector 검색 | AI 답변 + 근거 문서 출처 제공 |
| 예외 | 권한 밖 문서에 관해 질문한다 | RBAC 필터링에서 권한 없는 문서를 제외하고, 문서 존재 여부도 응답에 노출하지 않음 | 해당 문서를 뺀 답변(또는 결과 없음) — 문서 유무 미노출 |

## 4. 예시 (최소 2개, 실제 문장 인용)
- **입력**: "사용자가 접근할 수 없는 파일은 검색 결과, 요약, AI 답변의 근거 문서에 포함되지 않아야 한다" 는 원칙에 따른 질의.
- **기대 출력**: 사용자 권한 내 문서만 근거로 삼은 AI 답변과 출처 목록.
- **입력**: 원문 플로우 "권한 없는 문서 제외 → 문서 존재 여부도 노출하지 않음"에 해당하는 권한 밖 질의.
- **기대 출력**: 권한 밖 문서가 완전히 배제되고, 그 문서의 존재 여부조차 드러나지 않는 응답.

## 5. 상세 요구 (번호 목록, "~해야 한다")
1. 질문 처리 전에 사용자 인증을 수행해야 한다.
2. 인증된 사용자의 역할·부서·그룹을 확인해 접근 가능한 문서 범위를 계산해야 한다.
3. RBAC 조건으로 메타데이터를 필터링해 허용 문서만 검색 대상으로 삼아야 한다.
4. 허용 문서에 대해서만 Graph/Vector 검색을 수행하고 AI 답변과 출처를 생성해야 한다.
5. 권한 없는 문서는 검색 결과·요약·근거 문서에서 제외해야 한다.
6. 권한 없는 문서의 존재 여부조차 응답에 노출하지 않아야 한다.

## 6. 다루는 데이터 (해당 시)
- 입력: 사용자 질문, 사용자 인증 정보(역할/부서/그룹/프로젝트 참여 여부).
- 참조: 문서 메타데이터(고객사, 프로젝트, 민감도, 소유 부서), 권한 정책(허용 그룹, 차단 조건, 보존 기간, 감사 필요 여부).
- 출력: AI 답변, 근거 문서 출처.

## 7. 수용 기준 (체크박스 최소 3개, 참/거짓 판정 가능)
- [ ] 질문 처리 시 인증·역할 확인 후 접근 가능한 문서 범위가 계산된다.
- [ ] RBAC 조건으로 필터링된 허용 문서만 Graph/Vector 검색 대상이 된다.
- [ ] 권한 없는 문서가 검색 결과·요약·AI 답변 근거에 포함되지 않는다.
- [ ] 권한 없는 문서의 존재 여부가 응답에 노출되지 않는다.
- [ ] AI 답변에 근거 문서 출처가 함께 제공된다.
