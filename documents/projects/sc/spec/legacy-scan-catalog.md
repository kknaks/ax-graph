# 레거시 스캔·목록화

> 한 줄 정의: 데이터 관리자가 기존 공유폴더를 전체 스캔하면, 시스템이 파일 목록과 기본 메타데이터를 추출·분류하고 활용 상태를 판단해 통제 가능한 목록을 얻는다.

## 1. 요구 배경
- **현재 불편(as-is)**: 고객사 데이터가 네트워크 공유폴더에 집중되어 있고 별도 문서관리시스템 없이 데스크탑을 파일 서버처럼 사용한다. "파일이 어디에 있는지 담당자 기억에 의존"하고 "최신 파일과 과거 파일 구분"이 어려워, 담당자 변경·퇴사 시 업무가 단절되고 잘못된 자료 기반 의사결정 위험이 커진다.
- **필요 이유**: 즉시 이전이 아니라 기존 데이터를 먼저 "찾을 수 있고 통제 가능한 상태"로 전환해 이후 단계적 이전·보관의 기반을 만든다.

## 2. 기능 정의
- **핵심 동작**: 기존 공유폴더를 전체 스캔한다.
- 스캔 결과로 파일 목록을 생성한다.
- 각 파일의 기본 메타데이터(위치·속성 등)를 추출한다.
- 고객사/프로젝트/부서 기준으로 파일을 분류한다.
- 활용 상태(활성 데이터 / 보관 후보 / 정리 검토 대상)를 판단해 표시한다.

## 3. 유저 플로우 (반드시 표, 케이스별)

| 케이스 | 행동 (사용자가 한다) | 과정 (시스템이 처리) | 결과 (산출물) |
|---|---|---|---|
| 정상 | 데이터 관리자가 대상 공유폴더를 지정해 전체 스캔을 실행한다 | 폴더를 순회해 파일 목록을 만들고 기본 메타데이터를 추출한 뒤 고객사/프로젝트/부서 기준으로 분류하고 사용 빈도로 활용 상태를 판단한다 | 활성/보관 후보/정리 검토 대상으로 구분된 파일 목록(메타데이터 카탈로그) |
| 예외 | 관리자가 중복·불명확한 파일이 섞인 폴더를 스캔한다 | 활용 상태를 "정리 검토 대상"으로 표시하고 현업 확인이 필요한 항목으로 분리한다 | 정리 검토 대상 목록 — 현업 확인 대기 상태로 남는다 |

## 4. 예시 (최소 2개, 실제 문장 인용)
- **입력**: "기존 공유폴더는 즉시 폐기하거나 전면 이전하지 않는다. 먼저 전체 현황을 파악하고, 회사가 통제 가능한 목록으로 전환한다."
  - **기대 출력**: 대상 공유폴더 전체를 스캔한 파일 목록 + 기본 메타데이터가 카탈로그로 생성된다.
- **입력**: "고객사/프로젝트/부서 기준 분류" 후 "활용 상태 판단"이 필요한 상황.
  - **기대 출력**: 각 파일이 고객사/프로젝트/부서로 분류되고, 최근 사용은 활성 데이터, 낮은 사용 빈도는 보관 후보, 중복/불명확은 정리 검토 대상으로 판정된다.

## 5. 상세 요구 (번호 목록, "~해야 한다")
1. 지정된 기존 공유폴더를 전체 스캔해 파일 목록을 생성해야 한다.
2. 각 파일의 기본 메타데이터(파일 위치·속성 등)를 추출해 기록해야 한다.
3. 파일을 고객사/프로젝트/부서 기준으로 분류해야 한다.
4. 사용 빈도·중복 여부를 근거로 활용 상태를 활성 데이터/보관 후보/정리 검토 대상 중 하나로 판단해야 한다.
5. 원본을 이동하지 않고, 레거시 파일의 현재 위치를 정확히 기록해야 한다.
6. 정리 검토 대상(중복/불명확)은 현업 확인이 필요한 항목으로 분리해 표시해야 한다.

## 6. 다루는 데이터 (해당 시)
- 입력: 기존 공유폴더의 파일과 폴더 구조.
- 저장: 파일 목록과 기본 메타데이터(파일 위치, 속성, 고객사/프로젝트/부서 분류, 활용 상태).
- 출력: 활용 상태별로 구분된 통제 가능한 파일 목록(메타데이터 카탈로그).

## 7. 수용 기준 (체크박스 최소 3개, 참/거짓 판정 가능)
- [ ] 지정한 공유폴더를 스캔하면 파일 목록이 생성된다.
- [ ] 목록의 각 파일에 위치를 포함한 기본 메타데이터가 기록된다.
- [ ] 각 파일이 고객사/프로젝트/부서 기준으로 분류된다.
- [ ] 각 파일의 활용 상태가 활성 데이터/보관 후보/정리 검토 대상 중 하나로 표시된다.
- [ ] 원본 파일이 이동·삭제되지 않고 현재 위치가 그대로 기록된다.
