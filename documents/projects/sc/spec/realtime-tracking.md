# 실시간 트래킹

> 한 줄 정의: 데이터 관리자가 공유폴더/신규 저장소의 파일 변화를 겪으면, 시스템이 이벤트 감시와 주기 전체 스캔을 병행해 메타데이터를 항상 최신 상태로 반영해 준다.

## 1. 요구 배경
- **현재 불편(as-is)**: 파일이 생성·수정·이동되어도 카탈로그에 반영되지 않아 "최신 파일과 과거 파일 구분"이 어렵고, 누락·중복·권한 변경이 시간이 지나며 쌓인다. 이벤트만 감시하면 감시 장애 구간에서 변경이 통째로 누락되고, 스캔만 돌리면 반영이 느리다.
- **필요 이유**: 이벤트 기반 감시로 빠른 반영을, 주기적 전체 스캔으로 누락·권한 변경·중복 보정을 병행해 메타데이터의 최신성과 정합성을 동시에 확보한다.

## 2. 기능 정의
- 공유폴더/신규 저장소의 생성·수정·삭제·이동 이벤트를 실시간으로 감시한다.
- 주기적 전체 스캔으로 누락 확인, 권한 변경 확인, 중복 확인을 수행한다.
- 이벤트 감시 경로와 스캔 경로의 결과를 하나의 변경 이벤트 큐로 모은다.
- 큐의 변경을 소비해 메타데이터 카탈로그를 갱신한다.
- 갱신 결과를 변경 이력 저장·검색 인덱스 갱신·운영 대시보드 반영으로 연결한다.

## 3. 유저 플로우 (반드시 표, 케이스별)

| 케이스 | 행동 (사용자가 한다) | 과정 (시스템이 처리) | 결과 (산출물) |
|---|---|---|---|
| 정상 | 신규 저장소에 파일을 저장/수정한다 | 파일 생성/수정 이벤트 감지 → 변경 이벤트 큐 적재 → 메타데이터 갱신 | 변경 이력 저장, 검색 인덱스·대시보드 반영 |
| 예외 | (감시 장애 구간에) 파일을 이동/삭제했으나 이벤트가 누락됨 | 주기적 전체 스캔이 누락·권한 변경·중복을 대조 → 차이를 변경 이벤트 큐로 보정 적재 | 누락분 메타데이터 보정, 이력에 스캔 보정 기록 |

## 4. 예시 (최소 2개, 실제 문장 인용)
- **입력**: "생성/수정/삭제/이동 이벤트"가 공유폴더에서 발생.
  - **기대 출력**: 해당 파일의 위치·속성 메타데이터가 즉시 갱신되고 검색 인덱스에 반영된다.
- **입력**: 주기적 전체 스캔이 "누락 확인, 권한 변경 확인, 중복 확인"을 수행.
  - **기대 출력**: 이벤트로 놓친 변경과 권한 변경분이 보정되고, 중복 후보가 정리 검토 대상으로 표시된다.

## 5. 상세 요구 (번호 목록, "~해야 한다")
1. 공유폴더/신규 저장소의 생성·수정·삭제·이동 이벤트를 감시해 지연 없이 반영해야 한다.
2. 주기적 전체 스캔을 실행해 이벤트로 누락된 변경, 권한 변경, 중복을 확인해야 한다.
3. 이벤트 감시 결과와 스캔 결과를 단일 변경 이벤트 큐로 모아야 한다.
4. 큐의 변경을 소비해 메타데이터 카탈로그를 갱신해야 한다.
5. 메타데이터 갱신 시 변경 이력을 저장해야 한다.
6. 메타데이터 갱신 결과로 검색 인덱스를 갱신하고 운영 대시보드에 반영해야 한다.

## 6. 다루는 데이터 (해당 시)
- 입력: 파일 이벤트(생성/수정/삭제/이동), 스캔 결과(누락·권한 변경·중복).
- 저장: 변경 이벤트 큐 항목, 메타데이터(파일 위치/속성), 변경 이력.
- 출력: 검색 인덱스 갱신분, 운영 대시보드 반영 지표.

## 7. 수용 기준 (체크박스 최소 3개, 참/거짓 판정 가능)
- [ ] 파일 생성·수정·삭제·이동 이벤트가 감지되면 해당 메타데이터가 갱신된다.
- [ ] 주기적 전체 스캔이 이벤트로 누락된 변경·권한 변경·중복을 검출해 보정한다.
- [ ] 이벤트 경로와 스캔 경로의 변경이 동일한 변경 이벤트 큐를 통해 처리된다.
- [ ] 메타데이터 갱신마다 변경 이력이 저장된다.
- [ ] 메타데이터 갱신 후 검색 인덱스와 운영 대시보드가 반영된다.
