# 파일 데이터관리

> 한 줄 정의: 사용자가 파일을 올리고 내려받고 지우면, 시스템이 확장자·용량 제한과 미리보기·다운로드 이력·휴지통·백업으로 안전하게 보관·복구하고, 나아가 파일의 위치와 6축 메타데이터(책임부서·업무맥락·문서유형·PARA 상태·권한·보존정책)를 중앙 카탈로그에 등록·관리해 검색·AI 활용이 가능한 데이터 자산으로 전환한다.

## 1. 요구 배경
- **현재 불편(as-is)**: 여러 메뉴(자료실·직원 문서·계약·소프트웨어 등)에서 파일을 다루지만 업로드 제한·미리보기·삭제 복구·백업 같은 공통 처리가 표준화되어 있지 않다. 실수로 지운 자료를 되살릴 방법이 없고, 데이터·백업 관리도 개발업체에 매번 의존해야 한다. 더 근본적으로는 회사 데이터가 네트워크 공유폴더에 집중되어 "파일이 어디에 있는지 담당자 기억에 의존"하고, "최신 파일과 과거 파일 구분"이 어려우며, "폴더 권한 중심의 느슨한 통제"로 민감 데이터 노출 위험이 크고, "문서 위치/권한/맥락이 정리되지 않아" Graph RAG·AI 검색 도입이 어렵다.
- **필요 이유**: 파일·데이터 처리를 공통 기능으로 묶어 업로드 제한·미리보기·삭제 복구·엑셀 내보내기·백업을 일관되게 제공하는 한편, 파일의 위치와 속성을 다차원 메타데이터로 등록하는 중앙 카탈로그로 전환하면 자료 유실 위험과 운영 부담을 줄이고 "어디에 있고, 누가 접근 가능하며, 언제 보관/폐기되어야 하고, 어떻게 검색/활용할 수 있는지" 관리 가능한 자산으로 만든다.

## 2. 기능 정의
- 파일 업로드 시 확장자와 용량이 관리자가 설정한 제한을 만족하는지 검사한다.
- 이미지와 PDF 파일은 다운로드 없이 화면에서 미리보기로 보여준다.
- 여러 파일을 한 번에 업로드하고, 등록된 파일을 교체·삭제할 수 있게 한다.
- 파일 다운로드가 발생하면 누가 언제 어떤 파일을 받았는지 이력으로 기록한다.
- 삭제한 자료를 휴지통에 일정 기간 보관해 복구할 수 있게 하고, 관리자가 정기 자동 백업과 수동 백업, 데이터 엑셀 내보내기를 수행한다.
- 파일의 위치와 속성을 6축 메타데이터(책임 부서·업무 맥락(고객사/프로젝트)·문서 유형·PARA 상태·권한/보안·보존 정책)로 중앙 카탈로그에 등록·관리한다.
- 기존 공유폴더 데이터는 전체 스캔으로 파일 목록과 기본 메타데이터를 추출해 카탈로그로 합류시키고, 신규 파일은 저장 시점에 자동으로 카탈로그에 등록한다.

## 3. 유저 플로우 (반드시 표, 케이스별)

| 케이스 | 행동 (사용자가 한다) | 과정 (시스템이 처리) | 결과 (산출물) |
|---|---|---|---|
| 정상(업로드) | 사용자가 이미지·PDF 등 파일 여러 개를 선택해 업로드한다 | 확장자·용량 제한을 검사하고 통과분을 저장, 이미지·PDF는 미리보기를 생성하며 6축 메타데이터를 카탈로그에 등록한다 | 업로드된 파일 목록·미리보기와 메타데이터가 표시된다 |
| 정상(레거시 합류) | 관리자가 기존 공유폴더를 스캔 대상으로 지정한다 | 전체 스캔으로 파일 목록을 만들고 기본 메타데이터를 추출해 고객사/프로젝트/부서 기준으로 분류·등록한다 | 원본은 그대로 두고 통제 가능한 카탈로그 목록이 생성된다 |
| 예외(제한 초과) | 사용자가 허용되지 않은 확장자나 용량 초과 파일을 올린다 | 제한 위반을 감지해 해당 파일을 저장하지 않고 사유를 안내한다 | 거부 안내 메시지, 나머지 정상 파일만 업로드 |
| 예외(삭제 후 복구) | 사용자가 자료를 삭제하고, 이후 관리자가 복구를 요청한다 | 삭제 자료를 휴지통에 일정 기간 보관하다가 관리자 복구 시 원위치로 되돌린다 | 복구된 자료가 원래 위치에 다시 표시된다 |

## 4. 예시 (최소 2개, 실제 문장 인용)
- **입력**: "직원이 삭제한 자료도 관리자가 일정 기간 복구할 수 있도록 요청드립니다."
  - **기대 출력**: 직원이 지운 자료가 즉시 영구 삭제되지 않고 휴지통에 보존기간 동안 남아, 관리자가 목록에서 선택해 원위치로 복구한다.
- **입력**: "정기 자동 백업" / "관리자 데이터 백업"
  - **기대 출력**: 관리자가 필요 시 수동 백업을 실행하고, 시스템이 설정된 주기에 따라 데이터를 자동으로 백업본으로 남긴다.
- **입력**: "실제 운영 분류는 부서, 고객사, 프로젝트, 문서유형, 권한, 보존정책을 함께 사용하는 다차원 메타데이터 모델로 설계한다."
  - **기대 출력**: 한 파일에 대해 책임 부서(예: 영업/영업1팀), 업무 맥락(Client A·2026 유지보수 계약), 문서 유형(계약서), PARA 상태(Projects), 민감도(Confidential), 보존 티어(Hot·7년) 등 6축 메타데이터가 카탈로그에 함께 등록된다.

## 5. 상세 요구 (번호 목록, "~해야 한다")
1. 관리자가 업로드 허용 확장자와 파일 용량 제한을 설정할 수 있어야 한다.
2. 업로드 시 확장자·용량 제한을 위반하는 파일은 거부하고 사유를 안내해야 한다.
3. 이미지와 PDF 파일은 화면에서 미리보기로 표시해야 한다.
4. 다중 파일 업로드, 파일 교체, 파일 삭제를 지원해야 한다.
5. 파일 다운로드 이력(누가·언제·어떤 파일)을 기록해야 한다.
6. 삭제된 자료는 휴지통에 일정 기간 보관되고, 관리자가 복구할 수 있어야 한다.
7. 직원이 삭제한 자료도 관리자가 보존기간 내에 복구할 수 있어야 한다.
8. 데이터를 엑셀로 내보낼 수 있어야 한다.
9. 관리자가 수동으로 데이터 백업을 실행할 수 있고, 시스템이 정기 자동 백업을 수행해야 한다.
10. 파일마다 책임 부서·업무 맥락(고객사/프로젝트)·문서 유형·PARA 상태·권한/보안·보존 정책의 6축 메타데이터를 등록·관리하는 중앙 카탈로그를 제공해야 한다.
11. PARA는 폴더 구조의 최상위 기준이 아니라 데이터의 운영 상태·활용 목적을 표현하는 보조 메타데이터 축으로 적용해야 한다(Projects/Areas/Resources/Archives).
12. 기존 공유폴더 데이터는 즉시 전면 이전하지 않고, 전체 스캔으로 파일 목록과 기본 메타데이터를 추출해 카탈로그로 합류시키되 원본 위치를 정확히 기록해야 한다.
13. 신규 파일은 표준 저장 위치에 저장되는 시점부터 자동으로 카탈로그에 등록되어야 한다.
14. 보존 정책에 따라 데이터를 Hot(최근 1년)·Warm(1~3년)·Cold(3년 이상 아카이브)로 분리 운영하고, 아카이브 전환 시 원본은 장기 보관하되 메타데이터는 유지해야 한다.

## 6. 다루는 데이터 (해당 시)
- 입력: 업로드 파일(확장자·용량), 삭제 요청, 백업 실행 요청, 스캔 대상 공유폴더 경로.
- 저장: 원본 파일, 파일 위치·6축 메타데이터(책임부서·고객사·프로젝트·문서유형·PARA 상태·민감도·보존티어·접근그룹), 휴지통 보관 자료, 다운로드 이력, 백업본.
- 출력: 미리보기, 엑셀 내보내기 파일, 복구된 자료, 백업본, 메타데이터 카탈로그 목록.

## 7. 수용 기준 (체크박스 최소 3개, 참/거짓 판정 가능)
- [ ] 허용되지 않은 확장자나 용량 초과 파일을 업로드하면 저장되지 않고 사유가 표시된다.
- [ ] 이미지·PDF 파일을 다운로드하지 않고 화면 미리보기로 확인할 수 있다.
- [ ] 여러 파일을 한 번에 업로드하고, 등록된 파일을 교체·삭제할 수 있다.
- [ ] 파일 다운로드 시 누가 언제 받았는지 이력에 기록된다.
- [ ] 직원이 삭제한 자료가 휴지통에 보존기간 동안 남고, 관리자가 복구하면 원위치로 되돌아온다.
- [ ] 관리자가 데이터를 엑셀로 내보내고, 수동 및 정기 자동 백업을 확인할 수 있다.
- [ ] 한 파일에 대해 책임부서·업무맥락·문서유형·PARA 상태·권한·보존정책 6축 메타데이터가 카탈로그에 등록·조회된다.
- [ ] 기존 공유폴더 스캔으로 생성된 파일 목록이 원본 위치를 유지한 채 카탈로그에 합류하고, 신규 파일은 저장 시점에 자동 등록된다.
