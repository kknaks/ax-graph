# 개발 시 데이터베이스 선택 가이드 (DB 유형별 특징·적합 시나리오)

## 요약

새 서비스 개발 또는 취업 준비 시 키-밸류·관계형·그래프·도큐먼트·컬럼 패밀리·검색 엔진 등 주요 DB 유형의 특징과 적합 시나리오를 한 강의에서 정리한 영상이다. 결론은 일반적 상황에서 관계형 DB(데이터 정확도 우선)와 도큐먼트 DB(대량 입출력 우선) 중 선택하고, 목적별 서브 DB(Redis·Elasticsearch·Neo4j·Cassandra)를 조합하는 것이다.

## 핵심 내용

### 키-밸류 데이터베이스 — Redis

키-밸류 DB는 데이터를 키-밸류 형태로 저장하는 가장 단순한 구조로, 단독 메인 DB로의 실용성은 낮고 서브 용도로 주로 쓰인다. 대표 구현체인 **Redis**는 데이터를 하드디스크가 아닌 RAM에 저장해 수십~수백 배 빠른 속도를 낸다. 메인 DB를 별도로 두고 자주 쓰는 데이터를 Redis에 복사해 캐시처럼 제공하거나, pub/sub 구현에 활용하는 것이 일반적이다. 최근 Redis 단독으로 모든 기능을 커버하는 업그레이드 버전도 출시됐으나 실사용은 드문 편이다.

### 관계형 데이터베이스 (RDBMS)

테이블(표) 형태로 데이터를 저장하며 SQL로 조회한다. 대표 DBMS는 Oracle·MySQL·PostgreSQL이며, 데이터베이스 점유율 상위권 대부분이 관계형 DB다.

- **정규화**: 데이터 중복 제거를 위해 중복 데이터를 별도 테이블로 분리한다. 입출력 쿼리가 복잡해지는 단점이 있다.
- **트랜잭션**: 기본 내장 → 금융 거래 등 중요 기능을 안전하게 구현 가능.
- **적합 상황**: 데이터 정확도가 입출력 속도보다 중요한 경우, 범용 서비스.
- **명칭 유래**: '관계형'은 데이터 간 관계를 잘 표현해서가 아니라 수학 용어 '릴레이션(Relation, 행렬 개념)'에서 유래.

### 그래프 데이터베이스

노드(Node)를 만들고 노드 간의 관계(엣지)와 방향을 함께 저장한다. 자료 간 관계·방향을 중점으로 저장해야 할 때 적합하다. 개념 상세는 [[그래프-db]] 참조.

- 대표 DBMS: **Neo4j** / 쿼리 언어: Gremlin·Cypher 계열
- 적합 사례: 비행기 노선, SNS 친구 관계, 감염 경로 추적, **추천 서비스**

### 도큐먼트 데이터베이스

컬렉션(폴더) 안에 도큐먼트(파일)를 두고 각 도큐먼트에 JSON 형태로 데이터를 저장하는 방식이다. 대표 DBMS는 MongoDB·CouchDB·Firestore다. 개념 상세는 [[도큐먼트-db]] 참조.

주요 특징:
- 스키마 미리 정의 불필요 — 필드를 자유롭게 추가해도 에러 없음
- 정규화를 하지 않음 → 데이터 중복 허용, 입출력 문법이 단순
- 분산 처리를 염두에 두고 설계 → 수평 확장이 쉬움
- 단점: 분산 환경에서 DB 간 데이터 일관성이 떨어질 수 있음

적합 상황: 정확도보다 **대량 입출력**이 중요한 서비스.

### 컬럼 패밀리 데이터베이스

테이블·로(Row)를 만들고 로마다 자유롭게 컬럼을 추가해 기입하는 구조다. 표 형식이지만 유연하며, SQL이 아닌 자체 쿼리 언어(예: Cassandra의 CQL)를 사용한다. 정규화가 없어 입출력 문법이 단순하고 분산 처리 성능이 우수하다.

- 대표 DBMS: **Apache Cassandra, Google Bigtable**
- 적합 상황: 관계형 DB처럼 표 형식으로 저장하되 유연성이 필요하면서 대규모 입출력을 감당해야 하는 서비스

대규모 분산이 필요한 경우 수평 확장 전략은 [[파티셔닝-샤딩-대용량-데이터-분리-전략-비교]]와 함께 검토한다.

### 시계열 데이터베이스

타임스탬프 기반 데이터를 저장·분석하는 데 특화된 DB 유형으로, 시계열 데이터 저장 및 분석 목적에 한정해 사용한다.

### 검색 엔진 (Search Index DB)

대표 서비스: **Elasticsearch, Amazon CloudSearch**. 일반 DB로도 사용 가능하나 실제로는 검색 인덱스 보관 전용으로 주로 쓰인다. 기존 DB에서 데이터를 가져와 인덱스(색인)를 생성·보관하고, 검색 요청 시 인덱스 기반으로 빠른 결과를 제공한다. 부가 기능으로 실시간 검색어 추천·자동완성·오타 교정을 지원한다.

### 최종 선택 기준

| 우선순위 | 선택 DB | 대표 DBMS |
|---|---|---|
| 데이터 정확도 중요 | 관계형 DB | MySQL, PostgreSQL |
| 대량 입출력 중요 | 도큐먼트 DB | MongoDB |
| 캐싱·속도 최우선 (서브) | Redis | Redis |
| 관계·방향 데이터 중심 | 그래프 DB | Neo4j |
| 표 형식 + 대규모 분산 | 컬럼 패밀리 DB | Cassandra |
| 검색 기능 특화 | 검색 엔진 | Elasticsearch |
